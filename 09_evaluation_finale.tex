\chapter{Évaluation Finale du Cours}
\label{chap:evaluation}

Cette évaluation valide l'acquisition des compétences en hacking éthique
couvrant les aspects juridiques, méthodologiques, techniques (reconnaissance,
exploitation, post-exploitation, évasion) et professionnels (reporting).
Elle est structurée en quatre parties progressives.

\begin{boxinfo}
\textbf{Barème général :}
\begin{itemize}
    \item Partie A, QCM : 30 questions × 1 point = \textbf{30 points}
    \item Partie B, Vrai ou Faux : 10 questions × 1 point = \textbf{10 points}
    \item Partie C, Questions Ouvertes : 8 questions × 5 points = \textbf{40 points}
    \item Partie D, CTF Pratique : \textbf{20 points}
    \item \textbf{Total : 100 points}, Seuil de validation : 50/100
\end{itemize}
\end{boxinfo}

\noindent\textbf{Module 3, Scanning et Énumération}

\begin{enumerate}[resume]

\item Dans Nmap, le SYN Scan (\texttt{-sS}) est qualifié de \og{}furtif\fg{} car :
\begin{enumerate}[label=\Alph*.]
    \item Il n'envoie aucun paquet réseau
    \item Il n'établit pas la connexion TCP complète (handshake interrompu après SYN/ACK)
    \item Il utilise ICMP au lieu de TCP
    \item Il nécessite moins de droits que le TCP Connect Scan
\end{enumerate}
\textit{Réponse : B}

\item L'état de port \og{}Filtered\fg{} dans Nmap signifie :
\begin{enumerate}[label=\Alph*.]
    \item Le port est ouvert et un service écoute
    \item Le port est fermé
    \item Un pare-feu bloque l'accès sans répondre
    \item L'hôte est éteint
\end{enumerate}
\textit{Réponse : C}

\item L'énumération LDAP avec \texttt{ldapsearch} permet de :
\begin{enumerate}[label=\Alph*.]
    \item Scanner les ports ouverts d'un contrôleur de domaine
    \item Lister les utilisateurs, groupes et politiques d'un domaine Active Directory
    \item Craquer le mot de passe du compte Administrator
    \item Exécuter des commandes à distance sur le DC
\end{enumerate}
\textit{Réponse : B}

\item Kerbrute est utilisé pour :
\begin{enumerate}[label=\Alph*.]
    \item Cracker des tickets Kerberos hors ligne
    \item Énumérer les utilisateurs valides d'un domaine AD sans authentification
    \item Forger un Golden Ticket
    \item Scanner les ports Kerberos (88/TCP)
\end{enumerate}
\textit{Réponse : B (exploite le comportement différentiel du KDC)}

\end{enumerate}

\noindent\textbf{Module 4, Exploitation}

\begin{enumerate}[resume]

\item Une injection SQL de type \og{}Blind Time-Based\fg{} se caractérise par :
\begin{enumerate}[label=\Alph*.]
    \item L'affichage des résultats directement sur la page web
    \item Un délai de réponse révélant si la condition injectée est vraie
    \item Des messages d'erreur SQL visibles
    \item L'exfiltration de données via le protocole DNS
\end{enumerate}
\textit{Réponse : B}

\item Pour une cible Windows Server 2019 64~bits, le payload Metasploit
      correct pour EternalBlue est :
\begin{enumerate}[label=\Alph*.]
    \item \texttt{php/meterpreter/reverse\_tcp}
    \item \texttt{windows/meterpreter/reverse\_tcp}
    \item \texttt{windows/x64/meterpreter/reverse\_tcp}
    \item \texttt{linux/x64/meterpreter/reverse\_tcp}
\end{enumerate}
\textit{Réponse : C}

\item Le \sigle{XSS} de type \og{}Stored\fg{} est plus dangereux que le
      \og{}Reflected\fg{} car :
\begin{enumerate}[label=\Alph*.]
    \item Il s'exécute côté serveur
    \item Le payload est stocké en base de données et s'exécute pour tout visiteur
    \item Il ne nécessite pas d'encodage JavaScript
    \item Il contourne automatiquement le \sigle{WAF}
\end{enumerate}
\textit{Réponse : B}

\item La vulnérabilité SSRF permet à un attaquant de :
\begin{enumerate}[label=\Alph*.]
    \item Injecter des scripts dans les pages web
    \item Amener le serveur à effectuer des requêtes vers des ressources internes
    \item Modifier les timestamps des fichiers
    \item Élever ses privilèges vers root
\end{enumerate}
\textit{Réponse : B}

\item L'option SQLMap \texttt{--batch} :
\begin{enumerate}[label=\Alph*.]
    \item Accélère le scan en mode parallèle
    \item Répond automatiquement aux prompts interactifs avec les valeurs par défaut
    \item Exécute uniquement les tests de type blind
    \item Limite les requêtes à 100 par minute
\end{enumerate}
\textit{Réponse : B}

\end{enumerate}

\noindent\textbf{Module 5, Post-Exploitation et AD}

\begin{enumerate}[resume]

\item Lors d'un Kerberoasting, ce qui est extrait et cracké hors ligne est :
\begin{enumerate}[label=\Alph*.]
    \item Le hash du mot de passe du compte \texttt{krbtgt}
    \item Un ticket TGS chiffré avec le hash du compte de service ciblé
    \item Le hash NTLM de l'utilisateur authentifié
    \item La clé de session Kerberos du DC
\end{enumerate}
\textit{Réponse : B}

\item La commande Mimikatz \texttt{lsadump::dcsync} :
\begin{enumerate}[label=\Alph*.]
    \item Extrait les mots de passe de la mémoire LSASS locale
    \item Simule une réplication AD pour obtenir les hashs de tous les comptes du domaine
    \item Forger un Golden Ticket
    \item Créer un compte administrateur local
\end{enumerate}
\textit{Réponse : B}

\item Le Golden Ticket survit-il au changement de mot de passe de l'Administrateur ?
\begin{enumerate}[label=\Alph*.]
    \item Non, il est immédiatement invalidé
    \item Oui, il est basé sur le hash \texttt{krbtgt}, non sur celui de l'Administrateur
    \item Seulement si la durée de vie du ticket est inférieure à 10 heures
    \item Non, Windows invalide automatiquement les TGT anciens
\end{enumerate}
\textit{Réponse : B}

\item Le mouvement latéral via WMI (\texttt{wmiexec.py}) est plus furtif que PsExec car :
\begin{enumerate}[label=\Alph*.]
    \item Il utilise un port différent (135 vs 445)
    \item Il ne dépose aucun service temporaire sur le disque cible
    \item Il chiffre automatiquement les communications
    \item Il contourne Windows Firewall
\end{enumerate}
\textit{Réponse : B}

\item BloodHound est utilisé pour :
\begin{enumerate}[label=\Alph*.]
    \item Scanner les ports d'un Active Directory
    \item Visualiser les chemins d'attaque vers Domain Admin dans un environnement AD
    \item Cracker les tickets Kerberos hors ligne
    \item Contourner l'authentification MFA
\end{enumerate}
\textit{Réponse : B}

\end{enumerate}

\noindent\textbf{Module 7, Rapport et Remédiation}

\begin{enumerate}[resume]

\item Un score CVSS v3.1 de 9.8 avec le vecteur AV:N/AC:L/PR:N/UI:N signifie :
\begin{enumerate}[label=\Alph*.]
    \item Exploitable uniquement en local, complexité élevée
    \item Exploitable depuis le réseau, sans authentification, sans interaction utilisateur
    \item Nécessite des droits administrateur pour être exploité
    \item Impact limité à la confidentialité
\end{enumerate}
\textit{Réponse : B}

\item La différence entre \og{}correction\fg{} et \og{}compensation\fg{} en remédiation est :
\begin{enumerate}[label=\Alph*.]
    \item La correction est plus rapide que la compensation
    \item La correction supprime la faille à la source ; la compensation ajoute une barrière de protection
    \item La compensation s'applique uniquement aux vulnérabilités critiques
    \item Il n'y a aucune différence, les termes sont synonymes
\end{enumerate}
\textit{Réponse : B}

\item Le \sigle{CWE} (Common Weakness Enumeration) référence :
\begin{enumerate}[label=\Alph*.]
    \item Des vulnérabilités spécifiques avec un identifiant CVE
    \item Des catégories de faiblesses logicielles (ex : CWE-89 pour SQLi)
    \item Des scores de criticité de vulnérabilités
    \item Des techniques d'attaque dans MITRE ATT\&CK
\end{enumerate}
\textit{Réponse : B}

\item CVSS v4.0 introduit par rapport à CVSS v3.1 :
\begin{enumerate}[label=\Alph*.]
    \item Un nouveau système de scoring de 0 à 100
    \item Les métriques Threat (exploitabilité réelle) et Supplemental
    \item La suppression des métriques Environmental
    \item Une version spécifique aux vulnérabilités cloud
\end{enumerate}
\textit{Réponse : B}

\end{enumerate}

\section{Partie B : Vrai ou Faux}
\label{sec:vrai_faux}
% ==============================================================================

\textit{Consigne : Indiquer V (Vrai) ou F (Faux) et justifier en une phrase.}

\begin{enumerate}
    \item Il est légal de scanner n'importe quel site web sans autorisation.
          \hfill\textit{F, Le scan actif nécessite une autorisation écrite préalable.}
    \item Le SYN Scan (\texttt{-sS}) est plus furtif que le TCP Connect Scan.
          \hfill\textit{V, Il n'établit pas la connexion complète (demi-ouvert).}
    \item Un test \og{}Black Box\fg{} signifie que l'auditeur a accès au code source.
          \hfill\textit{F, C'est le \og{}White Box\fg{}.}
    \item Le Pass-the-Hash fonctionne principalement avec le protocole NTLM.
          \hfill\textit{V, NTLM utilise un challenge/réponse basé sur le hash.}
    \item Mimikatz nécessite \texttt{privilege::debug} avant \texttt{sekurlsa::logonpasswords}.
          \hfill\textit{V, \texttt{SeDebugPrivilege} est requis pour accéder à LSASS.}
    \item L'outil Hydra est utilisé pour les injections SQL automatisées.
          \hfill\textit{F, Hydra sert au brute force ; SQLMap pour les injections SQL.}
    \item Le Golden Ticket est invalide après un changement de mot de passe de l'Admin.
          \hfill\textit{F, Il est basé sur le hash \texttt{krbtgt}, pas de l'Admin.}
    \item Effacer les logs Windows avec \texttt{wevtutil cl Security} est une action silencieuse.
          \hfill\textit{F, Génère l'Event ID~1102 (log cleared), très visible pour un SOC.}
    \item Le pivoting permet d'accéder à des réseaux internes via une machine compromise en DMZ.
          \hfill\textit{V.}
    \item CVSS v3.1 et CVSS v4.0 utilisent la même échelle de scoring.
          \hfill\textit{V, Les deux vont de 0 à 10, mais v4.0 ajoute de nouvelles métriques.}
\end{enumerate}

\section{Partie C : Questions Ouvertes}
\label{sec:questions_ouvertes}
% ==============================================================================

\textit{Consigne : Répondre avec rigueur technique. Chaque réponse est notée sur 5 points.}

\begin{enumerate}
    \item Expliquez la différence entre un \textbf{Reverse Shell} et un \textbf{Bind Shell}
          en termes de direction de connexion et de contournement de pare-feux.
          Quel type est préférable contre un pare-feu bloquant les connexions entrantes ?

    \item Décrivez le \textbf{flux Kerberos} en 5 étapes (AS-REQ, AS-REP, TGS-REQ,
          TGS-REP, accès service) et expliquez précisément \textbf{pourquoi le
          Kerberoasting est possible}, quelle est la propriété du TGS qui le
          rend crackable hors ligne ?

    \item Pourquoi les attaques \textbf{fileless} sont-elles plus difficiles à
          détecter que les attaques traditionnelles basées sur des fichiers ?
          Quels mécanismes de défense sont efficaces contre elles ?

    \item Expliquez le concept de \textbf{Pivoting} et pourquoi il est nécessaire
          lors d'un pentest d'une architecture DMZ + LAN. Décrivez le workflow
          Chisel pour mettre en place un tunnel SOCKS5 entre l'attaquant et le
          réseau interne.

    \item Quelle est la différence entre la \textbf{détection statique (signature)}
          et la \textbf{détection comportementale (heuristique)} dans un
          \sigle{EDR} ? Quelle technique d'évasion contourne chacune d'elles ?

    \item Expliquez la différence entre \textbf{CVE}, \textbf{CWE} et
          \textbf{CVSS}. Pour la vulnérabilité EternalBlue (CVE-2017-0144),
          indiquez le score \sigle{CVSS v3.1} et justifiez chaque métrique
          de base (AV, AC, PR, UI, S, C, I, A).

    \item Qu'est-ce que le \textbf{DCSync} ? Quels droits sont nécessaires pour
          l'exécuter ? Comment un attaquant peut-il obtenir ces droits via
          Kerberoasting ? Quelle est la contre-mesure principale ?

    \item Expliquez la distinction entre \textbf{OWASP Top~10} et \textbf{OWASP
          Testing Guide v4.2}, pourquoi est-il important de les distinguer en
          pratique lors d'un pentest applicatif ?
\end{enumerate}

\section{Partie D : CTF, Capture The Flag}

\subsection{Scénario : Compromission Complète du SI LiZbiZ}
\label{subsec:ctf_scenario}

\begin{boxlizbiz}
\textbf{Contexte du CTF :}
Vous êtes connecté au réseau de test isolé. Votre adresse IP attaquante
est \texttt{10.10.10.100}. La cible principale est le contrôleur de
domaine \texttt{DC01} (192.168.10.5). L'objectif final est de récupérer
le fichier \texttt{C:\textbackslash{}Users\textbackslash{}Administrator\textbackslash{}Desktop\textbackslash{}flag.txt}
contenant le hash de validation.
\end{boxlizbiz}

\textbf{Tâches et barème :}

\begin{enumerate}
    \item \textbf{Reconnaissance OSINT} (2 pts) \\
          Effectuer une énumération DNS complète sur \texttt{lizbiz.local} :
          tenter un AXFR, identifier les sous-domaines via \texttt{crt.sh},
          lister les enregistrements MX et SOA. Documenter les résultats
          dans un tableau (IP, hostname, type de service).

    \item \textbf{Scanning actif} (3 pts) \\
          Lancer un scan Nmap complet (\texttt{-sS -sV -O -sC -p-}) sur
          les hôtes découverts. Identifier les ports ouverts, versions
          de services et vulnérabilités potentielles (scripts NSE
          \texttt{--script=vuln}). Confirmer la présence de
          \texttt{MS17-010} sur le serveur Windows interne.

    \item \textbf{Exploitation initiale} (4 pts) \\
          Exploiter l'injection SQL sur \texttt{http://203.0.113.10/login}
          pour extraire la base de données utilisateurs avec SQLMap.
          Accéder au panneau d'administration avec le compte administrateur
          extrait. Obtenir un shell sur le serveur via \textbf{LFI + Log
          Poisoning} ou \textbf{Command Injection}.

    \item \textbf{Escalade et pivot} (4 pts) \\
          Depuis le shell \texttt{www-data}, escalader en \texttt{root} via
          la mauvaise configuration sudo. Mettre en place un tunnel Chisel
          vers le réseau interne (192.168.10.0/24). Exploiter EternalBlue
          sur le serveur Windows (192.168.10.20) pour obtenir un shell
          \texttt{SYSTEM}.

    \item \textbf{Credential Harvesting et accès AD} (4 pts) \\
          Exécuter Mimikatz (\texttt{sekurlsa::logonpasswords}) sur le
          serveur Windows compromis. Utiliser le hash NTLM obtenu pour
          un Pass-the-Hash vers le Contrôleur de Domaine.
          Exécuter un DCSync (\texttt{secretsdump.py}) pour obtenir les
          hashs de tous les comptes.

    \item \textbf{Flag et rapport} (3 pts) \\
          Accéder au fichier \texttt{flag.txt} sur le bureau de
          l'Administrateur du DC. Rédiger une fiche de vulnérabilité
          complète pour le vecteur d'entrée principal (EternalBlue ou SQLi)
          au format Tableau~\ref{tab:fiche_sqli} avec score \sigle{CVSS
          v3.1}, référence MITRE ATT\&CK et recommandation.
\end{enumerate}

\begin{boxinfo}
\textbf{Grille d'évaluation du CTF :}
\begin{itemize}
    \item \textbf{Qualité de la documentation :} Toutes les actions
          doivent être horodatées et accompagnées de captures d'écran.
          Les hashes \sigle{SHA-256} des preuves sont obligatoires.
    \item \textbf{Précision technique :} Les commandes utilisées doivent
          être correctes et justifiées (mauvais payload = 0 point sur
          cette étape).
    \item \textbf{Fiche de vulnérabilité :} CVE/CWE, CVSS v3.1 avec
          vecteur complet, MITRE ATT\&CK, impact business, recommandation
          correction + compensation.
    \item \textbf{Éthique :} Toute action hors périmètre défini est
          éliminatoire.
\end{itemize}
\end{boxinfo}
